## 1. 项目功能概述

输入通话录音 ASR 转写文本（`left:` 外呼方 / `right:` 用户），输出对齐《对客反诈复核规范》的结构化复核结论：**正常/违规/涉诈判定 + 场景类目/子类目 + 风险等级 + 判断说明 + 原文证据**，供人工二次复核。

### 1.1 功能清单

| 功能 | 说明 | 入口 |
|---|---|---|
| 单通质检 | 对一通通话文本做质检，输出人类可读报告或 JSON | `scripts/inspect_text.py` |
| 批量评估 | 批量质检 CSV 语料，与人工标签对比输出 P/R/F1、类目/涉诈准确率 | `scripts/batch_eval.py` |
| 标签治理 / 自治演进 | 导出「规范判定 vs 人工标签」冲突（A/B/C 分桶）；`--apply` 自动沉淀候选规则；候选词人工审核晋升/丢弃 | `scripts/evolve.py` |
| 技能文件生成 | 从 `knowledge/rules.json` 生成/更新 17 个场景技能文件 `knowledge/skills/*.md`（幂等） | `scripts/build_skills.py` |
| 启发式离线兜底 | 未配置 `LLM_API_KEY` 时自动回退纯规则引擎，零依赖可离线运行 | 自动 |
| 结果缓存 / 去重 | 按内容哈希缓存结果；SimHash 近重复聚类去重降本 | `--cache` / `--dedup` |
| 证据校验 + 质量门控 | 违规结论的原文引用程序化校验；硬/软信号自动升级 tool loop 复核，`review_flags` 输出复核信号 | 自动 |

### 1.2 判定范围（rules.json v1.4 口径）

- **8 类违规场景**：引流第三方平台、贷款相关、法律服务、企业营销与招商服务、商品推销、商业地产、违规催收、其他；
- **涉诈场景（均高风险）**：机票退改签、手机租赁套路贷、证券投资类、网贷退息退费、个体工商户年报补录收费、贷款相关-ab贷、引导贷款用户添加第三方微信、套路运诈骗、验证码/短信转发诈骗；
- 判定原则：**就高不就低**；涉诈须单独标注且一律高风险。

### 1.3 三种质检模式

| 模式 | 触发方式 | 机制 |
|---|---|---|
| 快速模式（默认） | `QC_USE_TOOLS=false` 或 `--fast` | 检索增强单轮：预注入相似判例 + 规范小节 + top-k 技能，1 次 LLM 调用出结论 |
| 工具模式 | `QC_USE_TOOLS=true` 或 `--tools` | 完整 agent loop：模型多轮自主调用 `search_spec`/`get_scenario`/`retrieve_similar_cases`/`load_skill` |
| 两阶段升级 | `QC_ESCALATE_ON_SIGNALS=true`（默认） | 快速模式出结论后，硬信号直接升级 tool loop；软信号先自一致性采样，不一致才升级 |

## 2. 代码功能架构

### 2.1 总体分层

```
            CLI 层 (scripts/)
  inspect_text  batch_eval  evolve  build_skills
        │           │          │        │
        ▼           ▼          ▼        ▼
  ┌─────────────────────────────────────────────────┐
  │            核心 Agent 层 (qc_agent/)              │
  │  QcAgent.inspect() ── 统一质检入口                │
  │    ├─ 无 LLM → HeuristicInspector（离线兜底）     │
  │    ├─ fast：检索增强单轮 + 质量门控（默认）        │
  │    └─ tools：恒定 agent loop（LLM 多轮调用工具）  │
  │  ReflectAgent ── 冲突扫描 / 规则演进（evolve 用）  │
  └───────────────┬─────────────────────────────────┘
                  │ 工具与检索
     ┌────────────┼──────────────┬──────────────┐
     ▼            ▼              ▼              ▼
 search_spec  get_scenario  retrieve_similar  load_skill /
 (规范小节)   (场景规则)    _cases(人工判例)   web_search_fraud
     │            │              │              │
  ┌──────────────────────────────────────────────────┐
  │           知识与数据层 (knowledge/ + data/)        │
  │  spec.md（规范原文，切小节索引）                    │
  │  rules.json（结构化规则：场景/关键词/决策表/消歧）   │
  │  skills/*.md（17 个场景技能，含错题本区）           │
  │  sample_cases.csv（人工判例库，TF-IDF RAG 召回）    │
  └──────────────────────────────────────────────────┘
```

### 2.2 qc_agent 模块职责

| 模块 | 职责 |
|---|---|
| `agent.py` | 核心入口 `QcAgent.inspect()`：模式路由（heuristic/fast/tools）、agent loop、JSON 提取修复、质量门控与升级、结果缓存读写、超长截断 |
| `llm.py` | OpenAI 兼容协议客户端封装：超时、失败重试指数退避；未配 Key/未装 openai 时 `available=False` |
| `tools.py` | `ToolRegistry` 工具分发表 + tool schema：`search_spec` / `get_scenario` / `retrieve_similar_cases` / `load_skill` / `web_search_fraud`（可注入外部后端） |
| `prompts.py` | system prompt 运行时分节拼装（fast/tools 两套）；技能目录常驻 + 完整细则按路由注入；含 JSON 强制/修复指令与 `PROMPT_VERSION` |
| `knowledge_base.py` | 规范 `spec.md` 按标题切小节建索引；`rules.json` 动态加载/保存（供演进写回）；技能库装配 |
| `skills.py` | 场景技能库：frontmatter 解析、触发词 + TF-IDF 内容路由（top-k）、错题本区读写、内容指纹 `digest()` |
| `case_store.py` | 人工标注 CSV 判例库：加载、TF-IDF 相似判例召回（支持排除自身防评估泄漏） |
| `retrieval.py` | 零依赖中文字符 n-gram TF-IDF 检索引擎（被规范/判例/技能三处复用） |
| `heuristic.py` | 离线启发式质检器：知识库关键词 + 判例检索的确定性基线，LLM 失败时兜底 |
| `verify.py` | 证据校验：`evidence_quotes` 归一化子串 + 长引用分块匹配原文，产出 `evidence_verified` |
| `reflect.py` | 反射/演进 Agent：冲突扫描（A/B/C 分桶）、候选词提炼进 `candidate_keywords` 暂存区、错题定向落盘技能文件、候选词晋升/丢弃 |
| `labels.py` | 人工粗标签归一化为规范类目（可接受类目集、涉诈期望值、合规标签判定），批量评估口径依赖此模块 |
| `schema.py` | 输出契约 `InspectionResult` / `RiskLevel`：字段定义、to_dict/from_dict/to_json |
| `cache.py` | 结果缓存：内容哈希 → 结论 JSON，磁盘持久化（jsonl）、线程安全、周期落盘 |
| `dedup.py` | SimHash 近重复聚类：`cluster_texts` / `group_by_cluster`（batch_eval `--dedup` 消费） |
| `config.py` | dataclass 配置中心：极简 .env 加载 + 环境变量覆盖，全部默认值保证离线可跑 |
| `__init__.py` | 包导出：`Config` / `QcAgent` 等公共 API |

### 2.3 单通质检核心流程（`QcAgent.inspect()`）

1. **模式判定**：`llm.available=False` → 直接走 `HeuristicInspector`（source=`heuristic`）；
2. **缓存查询**：启用缓存时按 `模式+内容` 哈希命中即返（知识指纹纳入命名空间——rules/技能/prompt 变更后旧缓存自动失效）；
3. **fast 路径（默认）**：预检索相似判例 + 路由 top-k 技能 + 消歧规则注入 prompt，1 次 LLM 调用 → JSON 提取（兼容 markdown 包裹/尾逗号/嵌套，失败走修复轮）→ 证据校验；
4. **质量门控**：
   - **硬信号**（证据未命中原文 / 启发式命中涉诈但 LLM 判正常 / JSON 修复兜底）→ 直接升级 tools loop 复核，source=`llm-escalated`；
   - **软信号**（kNN 判例冲突 / 涉诈技能路由冲突 / 低自报置信度）→ 先自一致性采样 K-1 次（temp>0），核心结论（涉诈/违规/类目）不一致才升级；一致则保留并在 `review_flags` 标「已复核通过」；
5. **tools 路径**：恒定 agent loop——`while True: LLM.chat(messages, tools)`，无工具调用则输出结论，否则执行工具把结果 append 回 messages 继续，最多 `QC_MAX_TOOL_TURNS` 回合；
6. **异常兜底**：LLM 调用异常 → 回退启发式并在 `analysis_thought` 标注 `[LLM失败回退]`；
7. **写缓存**：仅 source 以 `llm` 开头的结论写入缓存。

### 2.4 演进闭环（ReflectAgent）

```
人工标注 CSV ──扫描──▶ 规范判定 vs 人工标签冲突（A/B/C 分桶导出）
                              │ --apply
                              ▼
        候选高危词 → rules.json 的 candidate_keywords 暂存区（不影响线上）
        错题案例  → rules.json evolved_examples + 对应技能文件错题本区
                              │ 人工审核
                              ▼
        --promote 晋升进生产 keywords ／ --discard 丢弃
                              │
                              ▼
        build_skills.py 重新生成技能文件（错题本区保留）
```

关键安全设计：演进词只进暂存区，启发式与 LLM 工具均不消费，**经人工审核晋升后才影响线上判定**。

## 3. 部署与环境准备

```powershell
# 1) 离线模式（启发式，零依赖）—— 无需任何安装即可运行
python scripts/inspect_text.py "left:我是投顾客服，联合上海证券创建官方福利群..."

# 2) LLM 模式（推荐测试重点）
pip install -r requirements.txt
copy .env.example .env      # 填 LLM_API_KEY / LLM_BASE_URL / LLM_MODEL
```

`LLM_BASE_URL` 兼容任意 OpenAI 协议服务（OpenAI / DeepSeek / 通义 DashScope 兼容模式 / GLM 等）。

### 3.1 关键配置项（.env / 环境变量）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `LLM_API_KEY` | 空 | 为空时走离线启发式回退 |
| `LLM_BASE_URL` | `https://api.openai.com/v1` | OpenAI 兼容网关地址 |
| `LLM_MODEL` | `gpt-4o-mini` | 模型名 |
| `LLM_TEMPERATURE` / `LLM_MAX_TOKENS` | `0.0` / `2048` | 采样参数 |
| `LLM_TIMEOUT` | `90` | 单次请求超时（秒），防批量 worker 挂死 |
| `QC_CASES_PATH` | `data/sample_cases.csv` | 人工标注判例库（列：`data_id,content,comment`） |
| `QC_USE_TOOLS` | `false` | 默认快速模式；true=完整 tool loop |
| `QC_MAX_TOOL_TURNS` | `6` | tool loop 最大回合数 |
| `QC_RETRIEVE_TOP_K` | `3` | 相似判例召回条数 |
| `QC_MAX_CONTENT_CHARS` | `6000` | 超长转写截断（保头尾），0=不截断 |
| `QC_LLM_MAX_RETRIES` / `QC_LLM_RETRY_BACKOFF` | `3` / `2.0` | 失败重试与指数退避 |
| `QC_BATCH_CONCURRENCY` | `4` | 批量并发数（CLI `--workers` 可覆盖） |
| `QC_CACHE_PATH` | 空 | 结果缓存路径，空=禁用 |
| `QC_ESCALATE_BELOW_CONFIDENCE` | `0.0` | 置信度低于阈值升级 tool loop，0=关闭 |
| `QC_ESCALATE_ON_SIGNALS` | `true` | 硬/软信号质量门控开关 |
| `QC_SELF_CONSISTENCY_K` / `QC_SC_TEMPERATURE` | `2` / `1.0` | 软信号自一致性采样次数与温度 |
| `QC_KNN_SIGNAL_MIN_SIM` | `0.25` | kNN 判例冲突软信号相似度门槛 |
| `QC_SOFT_CONFIDENCE_BELOW` | `0.9` | 自报置信度软信号阈值 |
| `QC_ROUTE_FRAUD_SIGNAL_MIN` | `0.25` | 涉诈路由冲突软信号阈值 |
| `QC_USE_SKILLS` / `QC_SKILLS_TOP_K` / `QC_SKILLS_DIR` | `true` / `3` / `knowledge/skills` | 场景技能库开关、路由条数、目录 |
| `QC_DISAMBIG_TOP_K` | `6` | 随文注入的消歧规则条数 |

## 4. 命令详解

### 4.1 单通质检 `scripts/inspect_text.py`

```powershell
python scripts/inspect_text.py "left:喂你好，我是*投顾客服..."
python scripts/inspect_text.py --file call.txt --json
echo "left:..." | python scripts/inspect_text.py
python scripts/inspect_text.py --tools -v -f call.txt
```

| 选项 | 说明 |
|---|---|
| `text`（位置参数） | 通话文本；不传则依次取 `--file`、stdin |
| `--file` / `-f` | 从 UTF-8 文件读取通话文本 |
| `--data-id` | 数据 ID（带入输出，可选） |
| `--json` | 仅输出 JSON 结果 |
| `--tools` | 完整 agentic tool loop（更慢更准） |
| `--fast` | 强制快速单轮模式 |
| `--verbose` / `-v` | 打印工具调用过程 |

**预期输出**（非 JSON 模式）：质检模式行 + 复核标签 / 是否违规 / 是否涉诈 / 风险等级 / 场景类目 / 判断说明 / 命中特征 / 原文证据 / 置信度 / 推理参考。
**异常**：未提供文本 → stderr 报错，退出码 2。

### 4.2 批量评估 `scripts/batch_eval.py`

```powershell
python scripts/batch_eval.py --csv data/sample_cases.csv --out results.csv
python scripts/batch_eval.py --csv data/eval_fresh_cases.csv --workers 6 --cache
python scripts/batch_eval.py --csv <大语料>.csv --sample 100 --dedup --cache
```

| 选项 | 说明 |
|---|---|
| `--csv` | 输入 CSV（缺省用 `QC_CASES_PATH`） |
| `--out` | 输出结果 CSV，默认 `results.csv` |
| `--limit` | 只评估前 N 条 |
| `--sample` | 均匀抽样 N 条（优先于 `--limit`） |
| `--workers` | 并发线程数（缺省 `QC_BATCH_CONCURRENCY`） |
| `--tools` | 完整 tool loop |
| `--dedup` / `--dedup-threshold` | 近重复聚类去重（阈值默认 0.9），同簇复用代表结论，source 标 `(dedup)` |
| `--cache` / `--cache-path` | 结果缓存（默认 `.cache/qc_results.jsonl`），中断可续跑 |
| `--verbose` / `-v` | 逐条打印进度 |

**评估口径**：`comment` 非空且非"正常/合规"= 人工违规；人工标签明确合规的样本不参与类目/涉诈准确率。
**输出**：结果 CSV（含 `pred_label`、`category_correct`、`fraud_correct`、`review_flags`、`source` 等列）+ 控制台指标报告（TP/FP/FN/TN、P/R/F1、类目准确率、涉诈准确率、耗时、LLM 实际调用次数）。

### 4.3 标签治理 / 演进 `scripts/evolve.py`

**冲突扫描（默认安全模式，不改规则）：**

```powershell
python scripts/evolve.py --csv data/sample_cases.csv --out conflicts.csv --cache --workers 8
python scripts/evolve.py --csv data/sample_cases.csv --apply    # 谨慎：自动演进
```

| 选项 | 说明 |
|---|---|
| `--csv` / `--out` / `--limit` / `--sample` / `--workers` / `--tools` / `--cache` / `--cache-path` | 语义同 batch_eval；`--out` 默认 `conflicts.csv` |
| `--apply` | 反射 Agent 把冲突沉淀为规则；提炼词只进 `candidate_keywords` 暂存区，**不影响线上判定** |
| `--quiet` | 静默模式 |

**输出**：`conflicts.csv`（全部）+ 按桶拆分 `conflicts_A_*.csv`（建议回标合规）/ `conflicts_B_*.csv`（真违规，核对类目）/ `conflicts_C_*.csv`（待人工复核）+ 冲突类型/标签 Top10 统计。

**候选词审核子命令（不需要语料/模型，直接操作 rules.json 后退出）：**

```powershell
python scripts/evolve.py --list-candidates                       # 查看待审核候选词
python scripts/evolve.py --promote 贷款相关                      # 晋升该类目全部候选词
python scripts/evolve.py --promote 贷款相关 --kw 砍头息 提前收费   # 只晋升指定词
python scripts/evolve.py --discard 贷款相关                      # 丢弃该类目全部候选词
```

### 4.4 技能文件生成 `scripts/build_skills.py`

```powershell
python scripts/build_skills.py            # 生成/更新 knowledge/skills/*.md
python scripts/build_skills.py --dry-run  # 只预览变更，不落盘
```

幂等；技能文件中"错题本"区块（errata 标记之间）会被保留；自动清理 rules.json 已删除类目的陈旧技能文件。**注意**：修改 `rules.json` 后必须重跑本命令，否则技能库与规则不同步。

### 4.5 回归测试

```powershell
python -m pytest tests/ -q     # 离线可跑，无需 API Key；当前基线 75 passed
```

## 5. 输出字段契约（InspectionResult）

| 字段 | 含义 |
|---|---|
| `label` | 复核标签，如「涉诈-高风险-证券投资类」 |
| `is_violation` | 是否违规（含涉诈） |
| `is_fraud` | 是否涉诈（涉诈一律高风险） |
| `risk_level` | 合规 / 低风险 / 中风险 / 高风险 |
| `scene_category` / `scene_subtype` | 场景大类 / 子场景 |
| `explanation` | 判断说明，格式【违规/涉诈类型+分析】 |
| `detected_features` / `evidence_quotes` | 命中特征 / 原文证据（程序化校验是否出自原文） |
| `confidence` / `analysis_thought` | 置信度 / 推理与参考依据 |
| `review_flags` | 质量门控触发的复核信号（供人工复核队列筛选） |
| `source` | 结论来源：`llm` / `llm-escalated` / `heuristic` / 带 `(dedup)` 后缀=复用代表结论 |

## 6. 测试建议与验收基线

### 6.1 建议测试范围

1. **离线启发式冒烟**（无 Key）：单通质检典型涉诈/违规/正常话术各若干条，验证不崩溃、结论合理、`source=heuristic`；
2. **LLM 快速模式功能**：`--json` 输出结构完整性、`--file`/stdin 输入、`--data-id` 透传；
3. **LLM 回归基线**：`data/eval_fresh_cases.csv`（28 条手写用例，覆盖全部类目，与判例库零重叠）——历史基线为违规检出 **R=1.000 / P=1.000**、类目 21/21、涉诈 10/10（DeepSeek 快速单轮）；
4. **批量能力**：并发、`--cache` 重跑近零成本（827 条重跑约 1s）、`--dedup` 结论复用正确性、中断续跑；
5. **evolve 全流程**：冲突扫描分桶导出 → `--apply` 后候选词只进暂存区（线上判定不变）→ `--list-candidates` / `--promote` / `--discard` 生效；
6. **build_skills 幂等性**：连续两次运行第二次 0 changed；`--dry-run` 不落盘；错题本区保留；
7. **质量门控**：构造证据不在原文的场景验证 `evidence_verified` 拦截与 `llm-escalated` 升级、`review_flags` 输出。

### 6.2 已知问题 / 边界口径（测试时注意）

- 人工历史标签存在噪声（招商加盟/会展无收费类曾被误标"引导投资理财"），批量评估表观分数受此拖累，冲突判定以 `evolve.py` 分桶结论为准；
- 边界口径未定：培训课程销售索要身份证照片是否算敏感信息违规，需业务确认；
- 自报 `confidence` 普遍饱和（0.95-1.0），不能单独作为质量指标，应以 `review_flags` 为准；
- 未配置 `LLM_API_KEY` 或未装 `openai` 时静默回退启发式，测试 LLM 路径前请确认输出首行"质检模式：llm"。

### 6.3 涉诈口径校正说明（近期变更）

违规类目（企业营销与招商服务、其他、商业地产、商品推销、引流第三方平台、法律服务、贷款相关、违规催收）已按最新规范降级为**违规而非涉诈**；100 条样本校正后涉诈判定准确率 0.550 → **0.880**，剩余 12 条错误均为模型漏检（预测=正常），测试时可重点关注漏检场景。
